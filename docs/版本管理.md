# 版本管理规范

> 适用范围：Cloudflare Deploy Engine 全部发布物（Git tag、GitHub Releases、CHANGELOG、发行包）。
> 目标：**让每一次发布可复现、可追溯、可回滚**；为 v0.1.0 之后的迭代奠定机制基础。

---

## 1. 版本号（SemVer）

格式：`MAJOR.MINOR.PATCH`（tag 前缀 `v`，如 `v0.1.0`）。

| 位 | 何时递增 | 示例 |
| :--- | :--- | :--- |
| MAJOR | 破坏性变更（部署协议/Core API/配置格式不兼容） | 1.0.0（首个稳定契约） |
| MINOR | 向后兼容的新功能（新插件轴/新目标/新模板体系） | 0.2.0 |
| PATCH | 向后兼容的缺陷修复 | 0.1.1 |

附加规则：
- 预发布：`v0.1.1-rc.1`（GitHub Release 勾选 Prerelease）
- 版本号唯一来源：`package.json` 的 `version` 字段（bump 时同步 CHANGELOG）
- 未发布阶段所有改动进入 `## [Unreleased]` 段，发版时归档为具体版本段

## 2. 分支与 Tag

```
main ──●──●──●──────────────►  （开发主线，始终可发布）
        \                 
         v0.1.0 (tag)     v0.1.1 (tag)
```

- **单一主线 `main`**：所有开发直接提交 main；`main` 始终处于"可发布"状态（CI 双作业 + 发布流水线门禁）
- **Tag 规则**：`v<SemVer>`（annotated tag `git tag -a`）；tag 默认可不签核（未签名项目，ADR-005）
- 发布后如需修复：在 main 修复 → bump PATCH → 打新 tag（本项目规模无需 LTS/backport 分支；若未来多版本并行再引入 `release/vX.Y` 分支）

## 3. 发布流程（可全自动）

前置：本地或 CI 已通过 `scripts\dev\build-release.ps1`（全门禁 + 产物 `dist/`）。

```text
1. bump：         更新 package.json version + CHANGELOG.md（Unreleased → 新版本段 + 链接）
2. 构建与验收：   build-release.ps1（Pester/密扫/完整性/尺寸/zip 断言）
3. 发布：         scripts\dev\release.ps1 -Version X.Y.Z [-Draft] [-Proxy http://127.0.0.1:7897]
                     （网络受限环境用 -Proxy；其他参数见脚本头部注释）
                     ├─ 校验 CHANGELOG 含该版本段
                     ├─ 创建并推送 tag vX.Y.Z（git 一并走代理）
                     ├─ GitHub API 创建 Release（body = CHANGELOG 该版本段）
                     └─ 上传资产：Cloudflare-Deploy-Engine-vX.Y.Z.zip + SHA256.txt + size-report.json
4. 验证：         Release 页面核对 body/资产/SHA256；下载一次 zip 抽查
5. 归档：         CHANGELOG 链接可跳转；README 徽章/版本引用更新（如适用）
```

## 4. Release Notes 规范（每条目结构）

```markdown
# <项目名> vX.Y.Z
<一句话变更概述>

## ✨ 新增        （新功能）
## 修复          （bug fix，注明影响面）
## 测试          （测试/门禁数据）
## 已知事项      （未更改的已知限制与安全提示）
## 📦 资产与校验  （zip + SHA256.txt + size-report.json 说明，提示 SmartScreen 口径）
## 安装          （3 步快速安装 + 指向使用说明）
```

- body 直接取自 `CHANGELOG.md` 对应版本段（**单一事实来源**，禁止手写两套）
- 资产必须含：发布 zip、`SHA256.txt`（内列 zip 与 exe 的 SHA256）、`size-report.json`（尺寸门禁实测）
- 发布后立即在 Release 页复核：tag 正确、3 个资产齐、SHA256 与本地一致

## 5. 版本与防回归挂钩

| 闸门 | 触发 |
| :--- | :--- |
| CI（push/PR） | 语法、Pester（70 项）、ScriptAnalyzer、密扫、plugins.json schema |
| CI（package 作业） | 模板完整性、neu 打包、尺寸门禁、zip 内容断言（无嵌套/关键文件）、产物 artifact |
| 发布流水线（本地 release 前置） | 上述全部 + `residue-scan` + `measure-memory` |

任何门禁不过 → 不得 bump/tag/release。

## 6. 约定与工具

- `CHANGELOG.md`：Keep a Changelog 风格；`[Unreleased]` 常驻顶部；每个版本段含版本锚点链接
- `scripts\dev\release.ps1`：唯一发布入口（幂等：tag/release 已存在则报错或 -Force 更新）
- 凭证：GitHub Token 经环境变量 `GH_PAT` 注入（**禁止写入任何文件/仓库**）；git 认证走一次性 `http.extraheader`
- 变更溯源：每个版本段的"修复"条目应可在《测试报告 1–5》中找到对应的缺陷编号（R1–R8 / F1–F4 等）
